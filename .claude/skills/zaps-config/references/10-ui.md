# UI Config — `ui` Block

TUI-local presentation. The whole block is optional and every field has a safe
default, so omitting `ui` (or any field) resolves to the defaults below.

## UiConfig Type

```ts
export type UiIconTheme = "nerd" | "unicode" | "ascii";
export type UiNotifications = "off" | "bell" | "osc9" | "osc9+bell";
export type UiFailOutput = "overlay" | "popup";
export type UiTaskMode = "background" | "pane";

export interface UiTaskConfig {
  defaultMode?: UiTaskMode; // default "background"
  popupPicker?: boolean; // default false
}

export interface UiConfig {
  icons?: UiIconTheme; // default "nerd"
  notifications?: UiNotifications; // default "osc9"
  failOutput?: UiFailOutput; // default "overlay"
  task?: UiTaskConfig;
  wideThreshold?: number; // integer ≥ 40, default 100
}
```

## Fields

| Field              | Values                                     | Default        | Description                                                                                  |
| ------------------ | ------------------------------------------ | -------------- | -------------------------------------------------------------------------------------------- |
| `icons`            | `"nerd" \| "unicode" \| "ascii"`           | `"nerd"`       | Glyph tier. The `ZAPS_ICONS` env var overrides the config value at startup.                  |
| `notifications`    | `"off" \| "bell" \| "osc9" \| "osc9+bell"` | `"osc9"`       | Out-of-band failure notification channel (OSC 9 desktop notification / bell).                |
| `failOutput`       | `"overlay" \| "popup"`                     | `"overlay"`    | Where the `f` failed-output view opens; `popup` escalates straight to a tmux popup.          |
| `task.defaultMode` | `"background" \| "pane"`                   | `"background"` | `Enter` mode; shell uses background when pane mode is unavailable. `Tab` needs pane support. |
| `task.popupPicker` | `boolean`                                  | `false`        | Use an `fzf` tmux popup picker instead of the in-app one.                                    |
| `wideThreshold`    | `number` (integer ≥ 40)                    | `100`          | Minimum terminal columns to show the detail pane; below it the pane collapses.               |

## Notes

- **`notifications`** fires on **task failure** only: `bell` rings the terminal
  bell, `osc9` emits an OSC 9 desktop notification, `osc9+bell` does both, `off`
  disables it. Only the task name is emitted — never log/output content.
- **`task.popupPicker`** falls back to the in-app picker when popup support, a usable client, or `fzf` is unavailable.
- **`wideThreshold`** has a hard floor of 40 in the schema; a value below the
  practical split minimum still collapses the detail pane.

## Backend capabilities and lifecycle

Shell retains service controls, URLs, logs, background task execution and in-app
overlays. Focus, zoom, capture/edit, pane task runs, popups and raw input are
unavailable. Keys have no side effect when unavailable; palette actions and hints
follow the same capability checks. Combined Docker-member rebuild actions are
also unavailable. A pane default becomes background for `Enter` in shell, while
`Tab` is disabled. Popup picker/failure-output preferences use in-app fallbacks
when unavailable before launch. A busy operation or lost daemon connection is
reported rather than opening another fallback.

UI startup needs interactive stdin and stdout. `q` or `Ctrl-C` leaves services and
ordinary background tasks running; `zaps`/`zaps attach` reopens the same session.
`Ctrl-D` asks for `y` confirmation before destruction; `zaps down` also stops owned
resources and destroys the session.

A managed tmux UI detaches only its uniquely verified outer client. If ownership
is ambiguous or unverifiable, it stays open with a manual-detach hint. A personal
tmux UI unsubscribes without detaching its host. Configured hook popups can fail
when their client detaches; ordinary background tasks continue.

The UI reports shutdown failures it receives. Managed teardown may remove its
pane before a later cleanup-error response arrives; a surviving CLI request can
report its explicit destruction result. Logs are held only in daemon memory, with
no session/log recovery or process adoption after daemon failure.

## Example

```ts
ui: {
  icons: "unicode",
  notifications: "osc9+bell",
  failOutput: "popup",
  wideThreshold: 120,
  task: { defaultMode: "pane", popupPicker: true },
}
```
